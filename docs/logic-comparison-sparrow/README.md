## 汇总结论

记录覆盖 Rust Sparrow 的 24 个比对单元（含 TUI 归属判定）及当前 `CodeResource/sparrow/src` 下全部 42 个 `.rs` 文件：40 个实现/应用模块文件与 2 个嵌套 TUI 测试文件。文件映射包含 `quantify/mod.rs`、`quantify/simd/mod.rs`、`util/mod.rs` 与 `tui.rs` 等模块入口。各记录的判定只描述源码对应与已列 fixture 覆盖。本轮已为 Clear 上界下的零损失碰撞、Hole/InferiorQualityZone 的 unsupported-hazard 失败、零预算搜索、`Some(0)` 失败上限及单 worker 搜索、双 worker Separator 重试和 Optimize phase cutoff 中的 QZone 异常传播增加跨语言测试；Hole/QZone 两侧都会失败，但 Rust panic 与 C++ exception 的语言级机制不同。worker 搜索夹具还核对 RNG-after、布局/Tracker 不变和失败候选不触发 trace callback。新增四实例 LBF 对照只证明固定 64/0/1 构造配置下的被测输入。仍未证明一般输入上的排序行为、完整 optimize→compress parity 或总体排料差异率。这些记录不等于完整移植完成或端到端数值 parity 已证明。2026-09-23 计划的“31/31”是实施状态记录，不能替代跨语言验收证据。

## Fixture 与证据边界

### 端到端 parity 的最小比较约定

每个端到端用例须保存固定 Rust 构建信息、输入实例、有效配置、显式 seed、feature 集及终止事件。按输入中的稳定 item ID 对齐两侧布局，精确比较已放置/未放置项目及其身份；对 trace 中的候选选择、阶段顺序、结束原因和离散状态按用例逐项核对。变换、loss、weight、width、density 等浮点字段使用其记录中的容差；如果最终布局字段没有已约定容差，必须在生成 oracle 时先定义并记录，不能只因 width/density 接近就判为排料结果一致。现有用例包括单件 warm-start、受控和默认阶段配置下的三件 cold-start optimize(None)、固定 worker 数压缩失败重试、零时限和正时限阶段退出，以及探索终止后 separator 状态与 best 快照分开的直接阶段交接。默认阶段配置 cold-start 由 listener 在探索、压缩各自首个 separation result 后请求 phase stop；TimeBased 正时限用例还验证 callback 跨过 deadline 后当前压缩尝试仍完成收尾、最终布局保持可行。这些固定触发点用例不代表自然运行至默认阶段时限、其他终止源、错误出口或一般输入的完整 parity。

### 对排料结果的影响

现有证据支持**定性风险判断**，仍不足以给出“多少比例的实例会不同”或“平均宽度/密度相差多少”的总体量化结论：四个固定输入已在 seed=42、64/0/1 下完成 Rust/C++ LBF 初始构造配对，精确比较项目身份与可行状态，并按记录容差比较变换和指标；但没有覆盖完整 optimize→compress，也没有跑完整默认时限或建立有代表性的实例分布。默认阶段配置 cold-start 仍只测一个三件方件实例，并由 listener 在探索、压缩各首个分离结果后停止。每条固定用例只证明其列明的事件和结果，不可据此外推到其他排料实例。

- **可能直接改变离散决策**：S10/S15 的候选排序与保留顺序会影响候选优先级；S10 固定排列和 S15 的 32 项混合非传递输入及精确同 loss tie 已有定向 fixture，但 Rust Ord 合同违反导致其他一般排序序列仍未定。S15 的平移/相似度/容量边界也有定向 fixture。S12/S18 的损失与权重也可能改变接受结果或最终布局。S03 的排序与宽度边界、S06 的离散旋转角距及本轮 f32 shrink/面积 cutoff/相似度阈值已按列明范围修复并由定向回归覆盖；这些局部测试没有测出多实例最终布局差值，且 S06 相似度 C++ 测试只断言生产谓词边界。
- **可能改变搜索轨迹**：S02/S07 的随机数消耗、S11/S20 的短路与停止时机，仍可能改变其他配置下的迭代、压缩机会或限时预算内的搜索次数。多 worker 压缩、探索失败后的状态交接、默认配置阶段分离、探索初始报告后的 phase stop、零时限立即退出、FailureBased 与 TimeBased 的正时限到期收尾，以及 TimeBased 五点斜率均有固定 Rust reference；TimeBased 用例分别核对按实测 elapsed 计算的曲线和 callback 越过 deadline 后的单步收尾，不能保证完整自然搜索的相同迭代序号步长、自然完整阶段运行、其他 worker 数或一般实例分布。
