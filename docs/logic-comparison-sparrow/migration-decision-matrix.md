## 决策约定

- **明确目标**：冻结的 Rust Sparrow 当前源码、RustReference 工具链、依赖锁和构建特性是唯一行为 oracle。在相同实例、有效配置、显式随机种子和终止条件下，C++ 的候选选择、阶段决策及最终排料结果必须与该 Rust 构建一致。浮点数值按记录列明的容差比较，只有明确要求 raw-bit 的项目才要求逐位相同。
- **差异处理**：C++ 的 Result 错误通道、额外计数和防御校验可以保留，但不得改变上述条件下的成功路径结果、有效停止条件或随机流。发现 Rust 本身的缺陷时，也不能在 C++ 单边修正后继续声称 parity；须先建立稳定的 Rust 预期行为，或将其作为获批的共同算法修订。
- **待决项**：算法语义没有“Rust 或 C++ 二选一”的产品决策，Rust 基线是唯一目标。只有 Rust 行为本身没有稳定定义时，才暂停相应输入域的 parity 声明；S10 的非传递排序比较器必须先用固定 Rust 工具链建立可重复参考结果，不能用 C++ 标准库偶然排序结果替代 oracle。CLI/UI 的归属可以由宿主范围决定，但凡会影响算法输入或停止时机的行为仍须映射到 Rust。
- **优先级**：P0 = 阻止声称核心语义对齐，先定行为并建立验收；P1 = 核心实现/API 冻结前完成；P2 = 宿主集成或选定目标 feature 集的验收。优先级只表示实施顺序，不授权在纳入基线的路径上保留已知结果差异。
- **验收规则**：离散事件、阶段、选择结果和计数按测试断言精确核对；浮点量使用逐记录规定的容差；若声称位级或任意输入等价，必须另有真正执行 raw-bit 或覆盖相应输入域的测试。
