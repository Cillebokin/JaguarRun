# E2 编译与浮点行为固定记录（2026-10-21）

## 结论

JaguarCore 与 SparrowCore 的 MSVC qmake 目标已显式使用 `/fp:strict`。SparrowWasm 的 CMake 目标按编译器选择浮点选项：MSVC 使用 `/fp:strict`，Clang/GCC 路径使用 `-fno-fast-math -ffp-contract=off`。目前没有发现 `/fp:fast`、`-ffast-math` 或源码级浮点控制 pragma。

选择 `/fp:strict` 是为了让 MSVC 2019 与更新工具集使用相同的非收缩浮点模型。Microsoft 文档说明 `/fp:precise` 在 Visual Studio 2022 之前可能默认允许 FMA 收缩，而 `/fp:strict` 不生成浮点收缩；`/fp:strict` 的额外浮点环境支持可能影响性能，本轮未做性能基准。[Microsoft Learn：`/fp` 浮点行为](https://learn.microsoft.com/en-us/cpp/build/reference/fp-specify-floating-point-behavior?view=msvc-170)。`/O2` 是速度优化组合，不等于 fast-math。[Microsoft Learn：`/O` 优化选项](https://learn.microsoft.com/en-us/cpp/build/reference/o-options-optimize-code?view=msvc-170)

## 实际编译选项

本轮在 Windows x64、Qt 6.5.3 `msvc2019_64`、MSVC 工具集 14.29.30133 下执行。`cl` 实际横幅版本为 14.29.30159.0。

| 目标 | Debug | Release | 其他影响浮点/指令选择的选项 |
|---|---|---|---|
| JaguarCore | `/fp:strict /Zi /MDd /std:c++17` | `/fp:strict /O2 /MD /std:c++17 /DNDEBUG` | AVX2 仅用于 `SoaGeometryAvx2.cpp`，实际参数含 `/arch:AVX2`；`CONFIG+=jaguarcore_no_avx2` 的 Release 变体编译 `SoaGeometryAvx2Fallback.cpp`，未带 `/arch:AVX2` |
| SparrowCore | `/fp:strict /Zi /MDd /std:c++17` | `/fp:strict /O2 /MD /std:c++17 /DNDEBUG` | 无额外浮点模型选项 |
| JaguarCoreTests / SparrowCoreTests | `/fp:strict /Zi /MDd /std:c++17` | `/fp:strict /O2 /MD /std:c++17 /DNDEBUG` | Jaguar Release 测试另加 `/UNDEBUG` 与 `/FI TestReleaseAsserts.h`，属于断言配置 |
| SparrowWasm CMake（非 Emscripten 本机分支） | — | MSVC `CXX_FLAGS` 含 `/O2 /MD /fp:strict` | 本机 CMake wrapper 编译通过 |
| SparrowWasm CMake（Emscripten 分支） | 未取得实际命令 | 源配置为 `-pthread -fno-fast-math -ffp-contract=off` | 当前 shell 未找到 `emcmake`、`emcc`、`em++`，工作区也没有该分支的 CMake 编译数据库；因此这里只能确认配置，不能声称已核实真实 Emscripten 命令 |

Qt 6.5.3 的 qmake `win32-msvc` 基础配置提供 Debug 的 `/Zi /MDd`、Release 的 `/O2 /MD`，没有自行设置 `/fp:*`。项目现在在 JaguarCore 公共 `.pri` 与 SparrowCore 各 qmake 目标中显式设置浮点模型。Debug/Release 的优化和 CRT 选项不同，浮点模型相同。

JaguarCore 的 Debug/Release qmake 生成阶段会提示 `simd.prf` 找不到 `qt_build_config`；构建仍退出 0，AVX2 源的真实命令含 `/arch:AVX2`，标量分支也实际编译了 fallback 源。该 Qt feature 提示没有导致当前目标构建失败。

## 验证结果

- JaguarCore Debug、Release 和 `jaguarcore_no_avx2` Release 构建均退出 0；AVX2 与标量变体的实际编译选项已逐一检查。
- SparrowCore Debug、Release 构建均退出 0；两套 Tests 目标的 Debug、Release 编译也退出 0。
- SparrowCore 与 JaguarCore 的 Release 全量 runner 均退出 0。SparrowCore 两个 S07 旋转错误出口在 Debug/Release 下均退出 0，输出的阶段和错误分类一致。
- SparrowCore Debug 全量 runner 退出 3；此前记录的 E5 `seed=4` 顶层定向入口也退出 3，而相同 Release 入口退出 0。同一 MSVC 14.29 工具集的 `/fp:precise` 对照仍复现 Debug 退出 3。本轮用调试器观察该定向入口约 6 分钟后，为避免一小时上限配置长期占用机器而停止；这次停止不计作通过或失败。另以 Debug 运行 `--e5-fixed-nonfinite-worker-rounds`，退出 0；同一固定输入重复两次、各执行 450 轮三 worker 搜索，raw loss 在断言容差内、weighted loss 为 NaN，且两次结果位模式一致。该结果说明此聚合夹具本身未复现退出3，Sparrow Debug 全量 runner 的根因仍未定位。
- JaguarCore Debug 全量 runner 退出 3。补齐 `JaguarCored.dll` 的运行时搜索路径后，CDB 捕获到未处理的 C++ 异常，调用栈为 `QuadTree::Constrict → RegisterIntoNode → RegisterHazard → runCollisionTests`；PDB 映射到 `TestCollision.cpp` 中 `coveringShape` 注册后的断言区域，抛出点为 `Quadtree.cpp` 的 `constricted_hazards has no partial child` 检查。该用例中的形状覆盖整个节点，所有子象限都可被归为 `Entire`，因此不会先产生 `Partial` 子项。锁定的 Rust 源 `qt_hazard.rs` 在相同阶段有同语义的 `debug_assert!`（第 113 行）；这是两侧源码共有的 Debug 路径，不是 `/fp:strict` 独有差异。Rust 侧此输入的 Debug 运行时结果本轮未单独执行。JaguarCore Release runner 退出 0；同工具集 `/fp:precise` Debug 对照也在该检查处退出 3。首轮未设置 DLL 搜索路径的直接启动返回 Windows `0xC0000135`，不计作 runner 结果。
- E2 保持“部分”：MSVC Debug/Release 的编译选项已核实，Jaguar Debug 退出已定位为 pinned Rust 同构的 Debug 检查；Sparrow Debug 的退出3仍待定位，且当前环境无 Emscripten 工具和该分支生成的编译数据库，不能宣称 Debug/Release runner 全部通过或 WASM 实际命令已核实。

此前已有的 VS 14.44 测试 EXE 与 VS 14.29 JaguarCore DLL 属于混合工具链，未作为本轮同工具链对照证据。
