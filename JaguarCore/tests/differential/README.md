# Rust/C++ differential oracle

This directory contains the first deterministic differential baseline for JaguarCore.

The RustOracle baseline uses Rust 1.98.1 and jagua-rs revision
`f5e2b5ffd14931f17a20ce283a2122e877953ceb`; invoke it with the pinned toolchain
and lockfile so it does not follow a different default rustup channel.

The files under `../Fixtures/RustReference/` use the jagua-rs external JSON schema. They intentionally contain small, deterministic cases so a failure identifies a geometry/import/state semantic mismatch rather than an optimizer ordering difference.

## B11 comparator coverage matrix

`JaguarCore/Tests/JaguarCoreTests.pro` compiles the eight `Compare*.cpp` files below, and `TestSupport.cpp::main` calls their eight differential entry points. `TestSoa.cpp` is a separate B10 comparator and is not part of the B11 `Compare*.cpp` count.

RustOracle references use Rust 1.98.1 and jagua-rs revision `f5e2b5ffd14931f17a20ce283a2122e877953ceb`, as recorded by [E4](../../../docs/complex/E4-oracle-fixture-baseline-2026-10-16.md). ## Expanding the oracle

1. Run RustOracle with the D5 toolchain and revision. Treat tests under `CodeResource/jagua-rs` as local-fork evidence unless a source comparison establishes identity with the pinned revision; the RustOracle lockfile does not pin that workspace path dependency.
2. Add a fixed Rust reference fixture or generated output under `rust_reference/`.
3. Add one C++ comparison with literals derived independently from the Rust run.
4. Compare feasibility, quantity conservation, stock, density, and hazard kinds before comparing coordinates.
5. Record float type, tolerance, item ordering, random seed, and whether a result came from an optimizer.

The current fixed collision matrix also records the boundary convention: CDE treats touching/tangent geometry as collision. A Surrogate negative case therefore uses a separate engine without an Exterior hazard, so it isolates fail-fast filtering from container-boundary semantics.

The B1 geometry fixture uses the locked Rust 1.98.1 toolchain and jagua-rs revision. Existing circle/edge/rect/point/polygon values come from the default oracle; extended B1 values come from `RustOracle --geometry-primitives-parity-only`. Scalar results use JaguarCore's `AlmostEqualRustF32` comparison; booleans, position classifications, and ordered vertices are exact. The extended values were checked against both Rust Debug and Release output through 2026-10-17.

The B1 second round compares Rust transformation matrix behavior through transformed origin/unit-axis probes and decomposed fields, plus exact `is_empty` cases. Edge intersection fixtures cover crossing, endpoint and T-junction contact, collinear overlap/touch, separated parallel edges, and an out-of-segment line intersection. Rectangle relation fixtures sample 1, 2, 3, 4, 8, and 16 ULP below `1.0f` to lock the `almost_relation_to` transition.

The B1 fourth round expands `geometry_primitives.txt` to 52 keys. It compares the independent `Point::x/y`, `Edge::bbox`, and `Rect::sides` accessors; all four `TransformableFrom` implementations; Point-left collision blanket dispatch, rectangle collision/near-collision trait booleans, and Edge/Rect dispatch in both directions; plus direct Rust calls to the four `SPolygon` derived-value helpers. C++ compares those helper values with fields produced by `SimplePolygon::Create`, since there is no matching public C++ helper API. At that round, Rust 1.98.1 Debug/Release oracle output matched the fixture and JaguarCore Debug/Release full test runners passed with assertions enabled.

The B1 fifth round expands the fixture to 65 keys for zero-length and underflowing edges, non-finite edge bboxes, rectangle boundary intersections/resizes/zero scale/quadrants, `SPolygon` helper panic/`Err` exits, and `TransformableFrom<SPolygon>` with a generated surrogate. Rust Debug and Release produce different surrogate pier values for this case, so the fixture stores `geometry.transform_from_surrogate_debug` and `_release`; the C++ comparator selects the key matching its build profile. Both profile-specific geometry differential entry points passed. The full `JaguarCoreTests.exe` runner was stopped after several minutes without output, so this round has no full-suite result.

The B1 sixth round expands the fixture to 80 unique keys with 15 finite-degeneracy references: raw zero-length `Edge` extension/scale/reverse/intersection, zero-width/zero-height `Rect` metrics/corners/edges/intersections/resizing/scaling, empty/singleton/duplicate/collinear convex hulls, degenerate direct Rust `SPolygon` helper outputs, and `Circle::bounding_circle` empty/single/containment cases. The 15 new keys match the locked Rust 1.98.1 Debug and Release outputs exactly; the targeted C++ geometry differential entry point passes in both profiles. The direct `SPolygon` helper metrics remain Rust-only reference data because JaguarCore exposes no matching static helper API. This round did not run the full `JaguarCoreTests.exe` suite.

The B1 seventh round expands the fixture to 82 unique keys. It directly compares `Rect::sides()` for zero-width and zero-height rectangles, and `Rect::bounding_rect()` for three unions involving degenerate rectangles. The Rust quadrant panic fixture now covers 1-ULP width, zero width, 1-ULP height, and zero height; Rust panics in all four cases while C++ returns quadrants containing zero-width or zero-height rectangles. Invalid `Rect::scale()` cases have the same rejection set: Rust panics and C++ returns `InvalidInput`. These failure channels remain distinct. Rust 1.98.1 Debug/Release oracle values match the fixture, and targeted C++ geometry differential runners built from the current workspace pass in Debug and Release. The full `JaguarCoreTests.exe` suite was not run. Rust `SPolygon` raw-point helpers still have no C++ public counterpart; valid polygon-derived values are checked through `SimplePolygon::Create`, and no mirror API was added under the frozen API boundary.

The B3 first round adds `surrogate_b3_debug.txt` and `surrogate_b3_release.txt`, generated by the locked Rust 1.98.1 `--fail-fast-parity-only` oracle at jagua-rs revision `f5e2b5ffd14931f17a20ce283a2122e877953ceb`. Each profile has 49 unique keys: all 22 generated poles and 6 piers across U/L/C shapes, fail-fast pole counts, convex-hull indices/area, and six surrogate collision detect/collect results. `CompareSurrogate.cpp` consumes every key with exact integer/index comparisons, RustF32 tolerance for geometry values, and exact collision outcome strings. Rust stdout matches both fixtures line-for-line; the targeted MSVC 2019 x64 C++ runner passes in Debug and Release with assertions active. The full `JaguarCoreTests.exe` suite was not run. Threshold-transition and generation-error cases remain outside this first matrix, so B3 stays partial.

The B3 second round expands each profile fixture to 72 unique keys. On a unit square, the pole coverage threshold is sampled one `f32` ULP below, exactly at, and one ULP above the coverage after two poles; pole counts are `2/3/3`, confirming strict `>` activation. The fail-fast ratio uses the same three points and selects `2/2/3` poles, confirming the inclusive `>=` coverage rule. Ratio endpoints `0` and `1` are valid; the smallest negative subnormal, the next `f32` above `1`, NaN, and both infinities are rejected. A valid offset square exercises the pier generator's `no ray found` exit (`Infeasible` in C++); a valid unit square plus an exclusion circle covering it exercises the pole search's `no pole found` exit (`InvalidPolygon` in C++). Rust Debug/Release output matches the fixtures exactly, and the targeted MSVC 2019 x64 runners pass in both profiles with Release assertions enabled. The 1000-pole safety guard itself was not runtime-exercised: reaching it requires nearly 1000 repeated pole searches, and its failure channel remains Rust assertion panic versus C++ `InvalidInput`. B3 is closed for this fixed differential matrix only; this is not a proof of equivalence for arbitrary geometry/configuration, and the full `JaguarCoreTests.exe` suite was not run.

`CompareBoundary.cpp` additionally locks the primitive convention that non-collinear
near-contact uses the configured tolerance while collinear overlap remains outside the
Rust `Edge::collides_with` predicate. The randomized problem-state test runs 1000 steps
per SPP/BPP/MSPP model and compares each state with a separately restored problem.
