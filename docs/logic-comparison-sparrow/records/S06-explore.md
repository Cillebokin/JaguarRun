### `disrupt_solution`（explore.rs:315-514）vs `DisruptSolution`（Exploration.cpp:602-860）
- 判定：基本等价（四步流程对应；面积 cutoff 和 1% 相似度比较现按 Rust f32 运算；实际轨迹已覆盖固定 seed 下的抽选和多子件搬迁顺序，C++ 按 hazard-key 槽位顺序复现 Rust 的 contained 收集顺序；其他随机流、几何及搬迁变换仍只在列出的固定证据范围内得到验证）。
- 证据与说明：
  1. **前置检查**：Rust `placed_items.len() < 2 → warn!+return`（:321-324）→ C++ `placements.size() < 2U → FromValue()`（Exploration.cpp:614-618，静默）。判定：一致（静默 vs warn，观测层）。C++ 额外仅在 `disruptionCount==0 && containedRelocationCount==0` 时直接返回（:591-595）；任一参数为正都会继续执行完整的交换与 contained 搬迁流程，两参数不能独立开关这两个动作。默认 1/1 下对应 Rust 硬编码的一次交换和一轮 contained 搬迁。
  2. **大件阈值（Step 1）**：Rust `total_ch_area = Σ(ch_area * qty)`（instance 层，:333-339）、`cutoff = total * percentile`（:341-343）、按 ch_area 降序累计 `ch_area*qty` 超过 cutoff 时取该项 ch_area 为 `ch_area_cutoff`（:344-372），计算使用 f32；C++ 对应实现（Exploration.cpp:620-662）将 hull area、需求乘积、总和、percentile cutoff 和累计量均存于 `float`，与 Rust 运算域对应。实际边界 fixture 的 Rust 面积/需求为 `(0.75,3)、(0.25,3)、(16,777,216,1)`：按 f32 输入顺序总面积为 `16,777,220`，乘 `0.9999999F` 得阈值 `16,777,218`；降序累计最终仍为 `16,777,218`，因条件是严格 `>`，cutoff 留在 0。旧 C++ double 总和为 `16,777,219`，阈值约 `16,777,217.3222781`，累计到中件后已越界并将 cutoff 设为 `0.75`，会排除面积 `0.25` 的小件。`exploration_area_boundary_reference.rs` 和 `TestRustF32AreaCutoffBoundary` 实际验证扰动选择；现行 C++ 已按 f32 对齐。该用例证明此临界输入，不外推为所有几何量生成值逐位一致。

## 结论
Algorithm 12 的主循环结构在 C++ 中大体对应；`Some(0)` 连续失败上限已改为可表达并由真实收缩失败 reference 验证。当前已按 Rust 运算域对齐 shrink/min-width、面积 cutoff 累计及面积/直径 1% 相似度谓词，三组临界边界都有 Rust 参考和 C++ 回归；证据只覆盖列出的算术边界，其中相似度 C++ 侧验证生产谓词，不等同于两侧随机扰动布局序列相同。离散旋转合法化已按 Rust 将有符号角差规范到 `[0, 2π)` 后取绝对值的规则修复，并由 Rust helper 与 C++ 实际 Explore 回归确认 359° 反例都选择 350°。同 loss 插入顺序已在锁定 Rust 1.98.1 基线及一个真实四次失败插入轨迹上对齐：插入位置 `[0,0,1,2]`、最终池 `[1,2,3,0]`，每次选中索引为 0，且逐项核对采样及后续 RNG 状态。另一个合法的 `{0°,37°}` 实际 Explore fixture 现在逐事件验证过滤候选上的 rand 0.10 coin-flipper 抽选、宿主交换顺序和 POI-contained 子件搬迁；该用例曾暴露 C++ 有界整数抽选虽均匀、却与 Rust iterator 抽选消耗/映射 RNG 不同，替换算法后其池/RNG/move trace 完全相同，两次失败布局按容差对齐。ZIGNOR 样本指纹另覆盖五个 seed、四个标准差、每组 128 个固定样本；其他 seed/参数、几何上游精度、其他 contained 布局及完整排料结果仍未证明完全一致。`PhaseReference` 是 C++ 回归数据，不能单独证明 Rust/C++ 端到端等价。

| item 需求超量：通过 `Layout` 直接构造 2 个同类型放置件，而实例需求为 1 | Debug 在第二次需求扣减时发生 `usize` 减法溢出 panic；之前布局已有 2 件、strip 已恢复，需求计数停在 0。Release 恢复成功，剩余需求回绕为 `usize::MAX` | Debug 抛 `std::underflow_error`，可观察状态同 Rust；Release 恢复成功并回绕为 `std::numeric_limits<std::size_t>::max()` | 状态与 profile 结果已对齐；Rust panic 与 C++ exception 属语言出口映射 |
| item 定义不匹配：dense index 与 external ID 相同，轮廓宽度由 1 改为 1.25 | Debug/Release 顶层 `optimize` 均接受，报告顺序 `[ExplFeas, Final]`，最终快照保留替代轮廓 | Debug/Release 的直接 `Restore` 和顶层 `Optimize` 均接受，报告顺序及最终轮廓与 Rust 对照一致 | 此边界已对齐；C++ 不再以当前实例轮廓相同作为恢复前置条件 |
| 碰撞快照结构不一致：保留一个 placement，清空 `cde_snapshot.dynamic_hazards` | Debug 在布局 quadtree 一致性断言处 panic，外层目标问题未替换；Release 直接恢复接受 1 个 placement、0 个动态 hazard。继续运行 `optimize` 时，Release 在 `CollisionTracker::new` 收集自身 hazard 时 panic，尚未发出 solution report | Debug 在临时 `Layout::Restore` 中抛 `std::logic_error`，外层目标问题未替换；Release 直接恢复保留 1 个 placement、0 个动态 hazard。顶层 `Optimize` 在 warm-start 预检处抛同消息的 `std::logic_error`，回调前失败 | 直接恢复状态和顶层失败/报告边界已对齐；C++ Release 在预检处提前映射 Rust tracker panic。该结论覆盖“动态 hazard 全空”夹具 |
| 碰撞快照结构不一致：2 个 placement 仅保留其中 1 个匹配的动态 hazard | Debug 在 `Layout::from_snapshot` 的 quadtree 一致性断言处 panic，外层目标问题未替换；Release 直接恢复接受 2 个 placement、1 个动态 hazard。顶层 `optimize` 在构造 tracker 时 panic，尚未发出 solution report | Debug 在临时 `Layout::Restore` 中抛 `std::logic_error`，外层目标问题未替换；Release 直接恢复保留 2 个 placement、1 个动态 hazard。顶层 `Optimize` 在 warm-start 预检处抛 `std::logic_error`，回调前失败 | 该部分缺失子集已按 profile 对齐；Release 的顶层 tracker 失败映射发生在 C++ 预检处。夹具只删去一个可匹配 hazard，不涵盖错误或额外 hazard |

本轮实现：`SPProblem::Restore` 取消 item-definition 预拒绝，先恢复布局/strip 再逐项扣减需求；Debug 下溢抛异常，Release 保留 `size_t` 无符号回绕。越界 `item_idx` 的现有 C++ 异常路径现由 Rust/C++ reference 固定其 Debug/Release 失败后状态和顶层回调边界。`Layout::Restore` 对缺少 placement hazard 的快照在 Debug 完成临时恢复后抛异常，在 Release 保留 Rust 接受的不完整状态；顶层 warm-start 对全空和已测部分缺失快照均在回调前复现 Rust 后续 tracker 初始化失败。C++ 只允许快照 hazard 为匹配 placement 的子集；错误/额外 hazard 仍拒绝。错误类别及语言出口映射见 [ERR-WARMSTART-RESTORE](../error-semantics.md#err-warmstart-restore)。

这四类已确认边界以五个 fixture case 覆盖状态、接受/失败结果及 solution-report 时点；hazard 缺失类有全空与非空部分缺失两个夹具，越界索引类目前只覆盖单个越界 placement。panic 与 C++ exception 的类型不相同。此结论不覆盖多个 placement 中越界项的顺序及其前序需求扣减、错误/额外 hazard、任意无效 slot metadata，也不保证任意损坏快照的行为相同。partial/重叠输入的报告类别也仍不代表完整需求或无碰撞布局。`verify-rust-reference.ps1` 已通过，Rust Debug/Release 各 114 个集成测试函数通过；SparrowCore Debug/Release 全量 runner 均以 exit code 0 结束。完整阶段验收仍见 `replication-roadmap.md`。
