## 〇、文档定位与使用规则

本文件是后续移植工作的总纲与导航，负责列出全部工作项、依赖关系、前置决策、风险、验收口径和完成定义。docs/complex 下的两份全景文档与 parts、parts2 拆分稿用于解释源码和结构，不是独立的进度状态来源；其结论与本清单冲突时，以本清单的当前状态及对应源码/测试证据为准。修订共享结论时，应同步全景稿与拆分稿。

权威层级如下，冲突时以较高层为准。第一层是 `docs/logic-comparison-sparrow/migration-decision-matrix.md` 与 `replication-roadmap.md`，它们是 Sparrow 侧的决策与验收合同，尤其是 Rust 作为唯一 oracle、离散量精确比较、浮点按字段容差比较、Debug 与 Release 同为范围等规则。第二层是本清单。第三层是 `docs/logic-comparison-sparrow/records/S01–S24.md` 等逐文件记录。旧版清单（修订 1）已废止，其中的状态与证据以本文件为准。

状态取值含义如下。"是" 表示完成标准已满足；必须同时注明支撑该结论的证据类型（静态核对、fixture 或已记录的运行测试），缺少验收要求的证据类型时标为"部分"。"部分" 表示已有实现或局部证据，但完成标准未满足。"否" 表示尚未开始或已确认缺失。"待决策" 表示必须先由负责人定案。"未核实" 表示本次未检查，不能据此判断。"前提不成立" 表示经核实原疑点的前提与源码不符。"已确认差异" 表示 Rust 与 C++ 的行为差异已在源码层面确认，但尚未有运行时证据。"待复现" 表示源码层面存在疑点，尚未运行验证。

证据边界需要注意。2026-10-16 已按 E4 在两处 oracle 独立运行锁定基线，并复核 Sparrow 的 13 个确定性生成输出；2026-10-17 又重算 B2、B4a，并在 Rust Debug/Release 下复核默认 cold-start reference、在 C++ Debug/Release 全套 runner 中复核对应跨语言用例。命令、版本、revision、哈希及 profile 差异见 [E4 执行记录](E4-oracle-fixture-baseline-2026-10-16.md)。第十四节其他 MSVC 执行记录由用户于 2026-10-16 提供，本次未独立复跑。

## 十二、验收标准（量化）

下列标准适用于各工作项的完成判定，具体数值以对应记录为准。
