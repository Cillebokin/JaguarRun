# S07. compress.rs 逐文件逻辑比对
**Rust**: `CodeResource/sparrow/src/optimizer/compress.rs`（80 行）
**C++**: `SparrowCore/Include/SparrowCore/Optimizer/Compression.h`（38 行）+ `Source/Optimizer/Compression.cpp`（381 行）
**判定**: 主循环与两种衰减策略在正常正时限/合法步长输入下结构对应，固定 reference 覆盖若干指定轨迹；FailureBased 的 `shrinkMin` 临界停机轮次已有一组 Rust/C++ fixture 对齐，其他指数下 pow 精度及宽度边界仍可能不同；TimeBased 计时起点也仍有偏移。直接阶段调用的 TimeBased `timeLimit=0` 已由 Rust/C++ fixture 对齐为不尝试压缩。worker seed 生命周期、宽度恢复顺序、f32 split 映射和 tracker moved-row 更新已按 Rust 对齐。TimeBased 正时限用例覆盖 deadline 跨越后当前尝试完成收尾及最终布局；未覆盖自然跑满默认 60 秒阶段、其他终止时点和一般布局。

## 函数逐条比对

### `compression_phase`（compress.rs:11-61）—— Algorithm 13
- C++ 对应：`Compress`（Compression.cpp:171-381，主双状态重载：188-381）。
- 判定：基本等价（主循环与两种衰减一致；三处差异如下）。
- 证据与说明：
  1. **min_width**：Rust `super::minimum_strip_width(&sep.prob)`（:18）→ C++ `CalculateMinimumStripWidth(instance, separatorState)`（调用：:231-232；Compression.cpp:56-127）。Explore 阶段另有实现（Exploration.cpp:61-144），不是逐行相同的副本：Explore 与 Compression 均按 Rust 的 f32/f64 运算次序计算；Compression 的单件方形临界阈值已由真实阶段 oracle 验证，Explore 的“所有离散角都不适配容器高度”正无穷边界也已由 `ExplorationMinimumWidthInfinityRustReference.tsv` 与 C++ 实际 Explore 回归对齐。该边界 fixture 的非法初始角不用于比较初始报告分类；两条路径的一般上游几何数值仍未被整体证明，详见 S06/S08。
  2. **初始 best_sol**：Rust `init_sol.clone()`（:19）→ C++ `bestSolution = initialSolution`（:218-219）：一致。
  3. **shrink_step_size（时间衰减）**：Rust `shrink_range.0 + ratio * (shrink_range.1 - shrink_range.0)`，`ratio = elapsed / time_limit`（:24-31，元组 `(max,min)`）→ C++ `step = shrinkMax + ratio * (shrinkMin - shrinkMax)`（:234-249，`ratio = elapsed_ms / timeLimit_ms`）。线性插值方向对应；数值域不同（Rust f32，C++ double），且 Rust `as_secs_f32()`、C++ elapsed 毫秒截断，可能在小时间/边界比较时取不同 step。时间锚点也不同：Rust 在计算 `min_width` 后启动局部 stopwatch（:18-20）；C++ 在指标计算、problem restore、Separator 创建、worker RNG 初始化和 `minimumWidth` 计算之后启动（:191-224），所以相同 phase deadline 下的曲线起点会有 setup 时间偏移。直接调用且 `timeLimit=0` 时，Rust 得到非有限 step 并在进度回调/压缩尝试前退出；C++ 已显式在循环内零时限分支退出。新增 `zero_time_time_based` Rust reference 与直接阶段 C++ comparator 核对该状态；正时限下的计时精度和起点差异仍在。
  4. **shrink_step_size（失败衰减）**：Rust `shrink_range.0 * r.powi(n_failed_attempts)`（:32-34，f32 运算）→ C++ 将 `shrinkMax`、`failureDecay` 转为 f32，计算衰减因子后以 f32 相乘，并将结果提升回 double（Compression.cpp:269-283）。停机阈值也按 f32 `shrinkMin` 比较。新增 Rust reference 将 `shrinkMax=0x3e4ccccd`、`shrinkMin=0x3e23d70b`、`failureDecay=0x3f4ccccd` 固定在 `step[1] == shrinkMin`；Rust 在等于下限时执行第二次失败尝试，之后停机。该 fixture 证明此临界配置的停机轮次一致；其他指数下 `powi` 与 `std::pow` 的实现精度仍未穷尽。
  5. **循环条件**：Rust `while !term.kill() && let step = shrink_step_size(...) && step >= config.shrink_range.1`（:39——`let` 链式条件：step 低于 min 即退出）→ C++ `while (!terminator.ShouldTerminate(iteration) && (maxIterations==0 || iteration<maxIterations))` + 循环体内按衰减分支对应精度比较 `step < minimumStep` 后退出（:230-232, 255-283）。FailureBased 的 `minimumStep` 使用 f32；TimeBased 仍使用 double。判定：结构一致；其他 f32/double 边界仍待覆盖。
  6. **宽度计算与停机**：Rust `width = best_sol.strip_width(); next_width = width*(1.0-step); if next_width < min_width || next_width >= width { break }`（:40-45，f32）→ C++ `width = bestSolution.StripWidth(); nextWidth = width*(1.0-step); if (!isfinite||<=0||>=width||(minimumWidth>0 && <minimumWidth)) break`（:260-266，double）。取值状态对应（两侧都基于 best 解）；f32/double 运算与比较可能在 `next_width` 接近宽度或 min_width 时改变退出边界，未有 ULP 边界 fixture。C++ 另有非有限/非正防御。
  7. **进度上报**：Rust `sol_listener.report_compression_progress(step)`（:46）→ C++ 原生 `listener->OnCompressionProgress(step)`（:268-269）；额外 `OnProgress` 仅通过显式传入的 C++ `OptimizationObserver` 提供（:270-277），不属于 Rust listener parity。
  8. **attempt_to_compress 调用与分支**：Rust `Some(compacted_sol) → report(CmprFeas); best_sol = compacted_sol`；`None → n_failed_attempts += 1`（:47-57）→ C++ `if (loss == 0.0F && metrics.feasible) { bestSolution=...; OnImprovement; PublishSolutionReport(COMPRESSION_FEASIBLE) } else { ++failures; if (maxConsecutiveFailures>0 && failures>=...) break; }`（:333-359）。判定：差异（两点：a) C++ 成功判据多一个 `metrics.feasible`【CalculateMetrics 的完整校验定义于 :16-53：remainingDemand==0 + ValidateSPSolution + layout.IsFeasible】——Rust 仅凭 `ot.get_total_loss() == 0.0`（:76）判定。正常路径 loss==0 ⇒ 可行，两侧一致；C++ 为防御性双重判据。b) C++ 额外 maxConsecutiveFailures 限流【默认 0 时不加失败次数限制】，Rust 无失败上限；两侧仍受终止器、步长和宽度停机条件约束）。
  9. **结束日志/返回**：Rust `info!` + `best_sol`（:59-60）→ C++ 无日志 + `CompressionResult{bestSolution, bestMetrics, history}`（:364-368）。判定：一致（返回形态差异同 S06 #1）。
  10. **fixture 覆盖**：`RustSppOptimizeCompressSingleItem.json` + `OptimizeCompressRustReference.tsv` 由 `optimizer_compress_reference.rs` 直接调用 Rust `optimize` 产生，C++ 由 `TestExploration.cpp` 消费。seed=3、单件 warm-start、separator `no_improvement_limit=0`、一 worker；比较阶段/报告顺序、两次 0.01 压缩步、最终宽度/密度/变换。该场景压缩第一次成功、第二次失败，且无需 worker move。新增 `RustSppCompressWorkerMove.json` + `CompressionWorkerMoveRustReference.tsv` 由 `compression_worker_move_reference.rs` 直接调用 Rust `compression_phase` 产生，C++ `TestCompressionWorkerMoveRetryMatchesRustReference` 消费：seed=42、两件同型矩形、warm-start 宽度 4.2、failure-based 步长 0.2/0.1、单 worker；两次压缩尝试均失败，但分离器每次都执行实际 moves，分别核对 438 evaluations/8 moves/5 iterations 与 362/6/4、progress/result 顺序、report 状态、loss/位置及最终 placements。Rust/C++ 的离散事件和计数精确匹配，几何/损失按 fixture 头部容差比较。此直接阶段用例不等同于完整 `optimize` 流程。`PhaseReference.tsv` 仍是 C++ 自回归基线，不能替代其他配置的 Rust 对照。

### `attempt_to_compress`（compress.rs:64-80）
- C++ 对应：`Compress` 循环体（Compression.cpp:290-319）。
- 判定：基本等价（收缩流程一致；宽度恢复顺序差异如下）。
- 证据与说明：
  1. **恢复到初始解与宽度**：Rust 每次压缩尝试先 `sep.change_strip_width(init_sol.strip_width(), None)`，再 `sep.rollback(init_sol, None)`（:66-67）；随后生成 split 并收缩（:70-72）。C++ 现在按相同次序执行 `ChangeStripWidth(width)`、`Rollback(bestSolution)`、split 抽样和 `ChangeStripWidth(nextWidth, split)`（Compression.cpp:290-308）。Rust `Separator::new` 构造时派生 N 个 worker seed；每次宽度变更立即重派生 N 个 seed。C++ 压缩入口通过 `ResetWorkerRngs(config.separator.nWorkers)` 对齐构造时消费（Compression.cpp:227），`ChangeStripWidth` 在 tracker 重建后立即按现有 worker 数重派生；本夹具的两次 split 与压缩接受/拒绝序列由 Rust/C++ 端到端结果核对。C++ 通用 Separator 创建仍采用延迟初始化，但压缩首次随机抽样前已显式初始化。
  2. **收缩宽度与随机分割点**：Rust `new_width = init_sol.strip_width() * (1.0 - r_shrink)`（:70），`split_pos = sep.rng.random_range(0.0..sep.prob.strip_width())`（:71）；C++ `nextWidth = width*(1.0-step)`，并以 `Uniform01F32() * static_cast<float>(width)` 计算 split。Rust 锁定的 rand 0.10.3 `random_range(f32)` 使用 23 位均匀值再乘 `high-low`；对 `low=0`，C++ 的 `Uniform01F32` 与 f32 宽度乘法采用相同映射。Rust RNG fixture 覆盖原语，端到端 fixture 覆盖指定两次 split 对应的几何分支；没有据此声称所有平台/所有浮点编译选项都 raw-bit 等价。
  3. **分离与成功判定**：Rust `sep.separate(term, sol_listener)` 返回 `(compacted_sol, ot)`，`ot.get_total_loss() == 0.0 → Some(compacted_sol)`（:75-79）→ C++ `separator.Run(...)`（:298-303）、`loss = separator.Tracker().TotalLoss()`（:310）及 `loss == 0 && metrics.feasible` 接受分支（:333-350）。判定：一致（额外可行性校验见上条 8）。
  4. **C++ 额外的逐轮指标**：每轮构造 progress 并通知 listener（:323-331）；loss/metrics 与 reject/exact 计数聚合见（:310-322）：C++ 额外（同 S06 #11）。
  5. **C++ 额外 `ValidationConfig`**：`CompressionConfig::Validate`（:146-158）：shrink 范围/failureDecay∈(0,1)/timeLimit 校验：C++ 额外（前置校验）。

## 结论
Algorithm 13 的主循环与正时限下的曲线方向已有源码核对和指定 Rust/C++ reference，但数值域和计时起点不完全相同。seed=3 warm-start 全流程覆盖一次成功和一次无 move 的失败压缩；seed=42 直接 compression-phase fixture 覆盖单/双 worker 下两次失败重试及每次实际 worker moves，并新增 `shrinkMin` 临界轮次参考。TimeBased 两条正时限 reference 分别核对五点曲线斜率和固定 callback crossing 到期后的当前尝试收尾，最终布局约 3.68；零时限直接阶段 fixture 核对不尝试压缩且初始布局不变。FailureBased 临界 fixture 仅证明列出的位模式和两次失败轨迹；其他指数下 `powi`/`std::pow` 精度、宽度边界舍入及 TimeBased stopwatch 起点仍开放。C++ metrics.feasible 校验和压缩限流字段仍按本表单独保留。

### 补充审计（2026-09-29）
1. **【核对确认：80 行逐项覆盖】** compress.rs 全量复核：compression_phase、闭包 shrink_step_size（两分支）、attempt_to_compress——主文 2 大节全覆盖无遗漏；`report_compression_progress(step)` 的 f32→double（S21 既定差异）已记。
2. **【遗漏补记：shrink_step_size 的 TimeBased 分支用 elapsed 而非剩余时间】** Rust `ratio = elapsed.as_secs_f32() / time_limit.as_secs_f32()`（compress.rs:29-30，**单调递增 0→1**，步长从 max 线性降至 min）；C++ `ratio = elapsed_ms / timeLimit_ms` 同向（Compression.cpp:245-259）。主文已记"线性内插 max→min"与毫秒/秒比值差，此处补记方向语义（无时间反向陷阱，判定不变）。
3. **【浅覆盖补全：循环条件 let 链的求值序】** Rust `while !term.kill() && let step = shrink_step_size(...) && step >= shrink_range.1`（compress.rs:39）——**每轮循环头部重算 step**；C++ 在循环体内先算 step 再检查 `step < shrinkMin → break`（:230-232,255-258）。主文条目 5 已记"移入循环体语义同"；补记：timeLimit 到达后 Rust 侧 terminator 的 ShouldTerminate 由 Compress 的 term 检查承担（既定 S20），step 本身可继续增大至 shrinkMin 之上——两侧均不因 step>max 停机（只因 <min 停机），判定维持。
4. **【历史分析，已被 2026-10-06 实测更正】** 早先按 rand 0.10.2 的 `Uniform::new` 溢出修正讨论了 `random_range(0.0..w)`，并误将 `sample_single` 的实现也归入 `new_bounded`；Rust 实际走 `UniformFloat::sample_single`，直接由 `u32 >> 9` 构造 23-bit `[0,1)` 值，再计算 `value0_1 * (high-low) + low`。当前 Cargo.lock 固定 rand 0.10.3；C++ split 已改为 `Uniform01F32() * static_cast<float>(width)`，与 low=0 的 Rust 表达式相同。
5. **【历史分析，已被 2026-10-06 实现与 fixture 取代】** 旧记录称 C++ 首个 split 在 worker seed 派生前生成。当前 C++ 压缩器在首个 split 前按 `config.separator.nWorkers` 调 `ResetWorkerRngs`；宽度恢复和收缩在 `ChangeStripWidth` 中立即重派生 worker RNG，并按 Rust 次序先恢复宽度、后 rollback、再抽 split。
6. **【验证边界（2026-10-07）】** optimizer_compress_reference.rs/TestExploration.cpp 对 seed=3 的单件 warm-start 全流程做跨语言比较；compression_worker_move_reference.rs/TestCompressionWorkerMoveRetryMatchesRustReference 对 seed=42 的两 worker 数配置分别核对两次失败压缩尝试，每次都含实际 move，并比较 separator 事件顺序、计数和 placements。optimizer_termination_handoff_reference.rs/TestTerminationHandoffMatchesRustReference 再核对一次 exploration 中断后以 separatorState 与 best solution 两状态启动压缩。S08 的 optimizer_cold_start_default_reference.rs/TestDefaultColdStartOptimizeMatchesRustReference 还在默认阶段配置下运行压缩至首个 separation result，核对配置、报告/事件、计数和布局；它不覆盖自然跑满 60 秒或完整 time-based 衰减曲线。其他终止时点、一般实例分布仍待参考。
7. **【稳定性复跑（2026-10-07）】** 双 worker 失败重试 Rust reference 在 Debug 下以独立测试进程连续运行 10 次均通过；只支持该固定 seed/夹具轨迹稳定，不扩展到其他 worker 数、运行时调度或一般实例。
